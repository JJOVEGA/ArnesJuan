## 3. Falsación propia — intentos de romper la implementación

Ejecutado sobre `src/formato.js` real (sólo llamadas, sin editar el archivo):

```js
listaClientes(null)                         // TypeError: Cannot read properties of null (reading 'filter')
listaClientes(undefined)                    // TypeError: Cannot read properties of undefined (reading 'filter')
listaClientes('Ana')                        // TypeError: nombres.filter is not a function
listaClientes({0:'Ana'})                    // TypeError: nombres.filter is not a function
listaClientes(42)                           // TypeError: nombres.filter is not a function
listaClientes(['Ana; Falsa', 'Luis'])       // "Ana; Falsa; Luis"        (esperado, sin hallazgo)
listaClientes(['Ana', 42, 'Luis'])          // "Ana; 42; Luis"
listaClientes(['Ana', {n:1}, 'Luis'])       // "Ana; [object Object]; Luis"
listaClientes(['Ana', 0, 'Luis'])           // "Ana; Luis"   (0 se omite, no es "vacío" ni "nulo")
listaClientes(['Ana', false, 'Luis'])       // "Ana; Luis"   (false se omite, ídem)
listaClientes(['Ana', NaN, 'Luis'])         // "Ana; Luis"   (NaN se omite, ídem)
listaClientes(['Ana', '   ', 'Luis'])       // "Ana;    ; Luis"  (espacios NO se omiten)
```

### Hallazgo H1 — `nombres` nulo/indefinido/no-array revienta con `TypeError` sin control
**Clase: `usuario/dinero`.**
**Repro:** `node -e "require('./src/formato.js').listaClientes(null)"` (o `undefined`, o
cualquier valor no-array: string, objeto, número) → lanza `TypeError` no controlado.
**Esperado:** ninguno de los dos criterios lo prohíbe explícitamente, pero la función está
documentada como la que arma el encabezado del informe mensual (`// Presentación: lista de
nombres de clientes para el encabezado del informe mensual.`); si el llamador no garantiza
un array (p.ej. un período sin clientes donde el campo llega `null`/`undefined` en vez de
`[]`), la generación completa del informe se cae con una excepción sin manejar en vez de
mostrar un encabezado vacío. Esto es lo que alguien vería (o dejaría de ver) en producción.
**Observado:** excepción sin capturar, tal como está.

### Hallazgo H2 — elementos no-string se incrustan literalmente en el encabezado
**Clase: `usuario/dinero`.**
**Repro:** `listaClientes(['Ana', {n:1}, 'Luis'])` → `"Ana; [object Object]; Luis"`;
`listaClientes(['Ana', 42, 'Luis'])` → `"Ana; 42; Luis"`.
**Esperado:** ninguno de los dos criterios habla de tipos, pero un encabezado con
`[object Object]` es exactamente el tipo de dato corrupto que un cliente podría llegar a ver
en un informe real si la fuente de datos entrega algo distinto de una cadena.
**Observado:** el valor se incrusta tal cual via `join`, sin validar ni convertir tipo.

### Hallazgo H3 — CA-02 no define con precisión qué es "vacío"; el código resuelve más y menos de lo que dice el criterio
**Clase: `contrato`** (forma "el código cubre MÁS de lo que el criterio promete", más su
reverso — el código cubre MENOS en otro subcaso —; `requirements/README.md` §«Cómo se
escribe un criterio que no se desmiente» / «Cuando el código cubre MÁS de lo que el criterio
promete» exige corregir esta asimetría en el mismo cambio que la descubre; no ocurrió en
este write-back).
- **Cubre MÁS:** `filter(Boolean)` omite también `0`, `false` y `NaN` — valores que no son
  "vacíos" ni "nulos" en el sentido literal del criterio (`['Ana', 0, 'Luis']` →
  `"Ana; Luis"`; ídem con `false` y `NaN`).
- **Cubre MENOS:** una cadena compuesta solo de espacios (`'   '`) **no** se omite —
  `['Ana', '   ', 'Luis']` → `"Ana;    ; Luis"` —, aunque visualmente sería razonable
  considerarla "vacía".
- El criterio no dice si "vacío" es la cadena `''` estricta, el resultado de un `trim()`, o
  "cualquier valor JS falsy". El código resolvió una interpretación (falsy de JS) sin que
  eso quede escrito en ningún lado. Esto no invalida CA-02 tal como está redactado hoy (que
  sigue siendo válido para `''`, `null`, `undefined`), pero es exactamente la ambigüedad que
  la sección de README pide no dejar sin resolver.

**No se intentó reproducir con "límite" numérico** porque CA-01/CA-02 no fijan ningún
número — no aplica la forma (b)/(c)/(d) del catálogo de criterios mal formados.

### 7. Falsación adicional — entradas no contempladas explícitamente por el REQ

Sobre `src/formato.js` real, sin editar:

```js
listaClientes(['Ana', ' ', 'Luis'])        // "Ana; Luis" — NBSP es whitespace de
                                                  // trim() (ECMA-262), se omite: correcto
listaClientes(['Ana', '​', 'Luis'])        // "Ana; ​; Luis" — U+200B NO es whitespace
                                                  // de trim(), se conserva: correcto
listaClientes(['Ana', new String('Luis')])      // lanza índice 1 — typeof 'object', correcto
listaClientes(['Ana', Symbol('x')])              // lanza índice 1 — typeof 'symbol', correcto
listaClientes(['Ana', , 'Luis'])                // "Ana; Luis" — hueco de sparse array se lee
                                                  // como undefined, omitido por CA-02
listaClientes(new Array(3))                     // "" — sparse total, todo omitido
listaClientes(class extends Array{}.from(['Ana','Luis']))  // "Ana; Luis" — Array.isArray
                                                  // es true para subclases
listaClientes(arguments)                        // lanza CA-03 — Array.isArray(arguments)
                                                  // es false: correcto, no es un arreglo real
listaClientes(new Proxy(['Ana','Luis'], {}))    // "Ana; Luis" — Array.isArray ve el target
listaClientes({})                                // lanza CA-03 (fila de la tabla de Notas
                                                  // confirmada)
listaClientes(['Ana', -0, 'Luis'])              // lanza índice 1 — typeof number
```
