## QA-201 — un REQ que no se puede leer desaparece del análisis y el resultado pasa a `disjunto`

**Clase:** `contrato` · **Severidad:** alta · **Criterios:** CA-04, CA-13, CA-24 de REQ-013.

`tools/arnes-paralelo.sh:205` lee cada REQ con `IFS= read -r -d '' texto < "$f" || :`. El `|| :`
**se traga el fallo de lectura**, y las líneas 211-212 descartan en silencio cualquier archivo del
que no se haya podido extraer un `Estado:`. El REQ no aparece en la lista, no aparece en ningún par,
y **nadie dice que faltó**: el recuento de la cabecera baja de 3 a 2 sin una palabra.

**Pasos de reproducción**

```bash
mk REQ-A 'hooks/lib.sh'; mk REQ-B 'tools/arnes-lectura.sh'; mk REQ-C 'hooks/lib.sh'
( cd "$P" && bash "$PAR" ); echo "rc=$?"          # control
chmod 000 "$P/requirements/REQ-C.md"
( cd "$P" && bash "$PAR" ); echo "rc=$?"          # el caso
```

**Esperado (CA-04):** REQ-C se declara `sin declarar`, colisiona con todos y el comando sale ≠ 0 —
o, como mínimo, el modo degradado de CA-13: «lo dice en su salida, sale ≠ 0 y no afirma que todo sea
disjunto».

**Observado:**

```
control:  Paralelismo por archivos — requirements/ (3 REQ evaluados)
            REQ-A vs REQ-C   colisiona  hooks/lib.sh        rc=1
caso:     Paralelismo por archivos — requirements/ (2 REQ evaluados)
            REQ-A vs REQ-B   disjunto
          Todos los pares son DISJUNTOS por archivos.        rc=0
```

Un archivo que la herramienta no pudo leer convierte un `colisiona` en un **«adelante»**. Es
exactamente lo que el arnés ya decidió para la cola de aprobaciones —«si la cola no se puede leer
entera —un byte NUL, un archivo sin permiso—, la puerta DENIEGA y el bloque derivado dice `sin
datos`: nunca 0» (`PENDING_APPROVAL.md`)— y aquí se resuelve al revés.

**Variante B, mismo defecto — byte NUL en banda.** `read -r -d ''` corta en el primer NUL; si el NUL
va antes de la cabecera, el REQ pierde su `Estado:` y se descarta igual, en silencio:

```bash
printf '# REQ-C\n\000\nEstado: en-revisión\nArchivos: hooks/lib.sh\n\n## H\n' > "$P/requirements/REQ-C.md"
( cd "$P" && bash "$PAR" ); echo "rc=$?"   # -> 2 REQ evaluados, "Todos los pares son DISJUNTOS", rc=0
```

«Bytes de control en banda» ya está catalogado como familia de evasión en REQ-007.

**Nota de diseño (no es hallazgo aparte, pero es el mecanismo que lo hace invisible):** descartar
por diseño los archivos sin `Estado:` («un archivo sin `Estado:` no es un REQ, es una nota») es
defendible; lo que no lo es es que la población evaluada se reduzca **sin decirlo**. Una línea
«N archivos de `requirements/` no se pudieron evaluar» convierte los tres casos en visibles.

## QA-202 — un archivo que todavía no existe no colisiona con el glob que lo alcanzará

**Clase:** `contrato` · **Severidad:** alta · **Criterio:** CA-08 de REQ-013.

CA-08 dice literalmente: «un glob que **no casa con ningún archivo existente** (un archivo aún por
crear, como `hooks/post-bash.sh` de REQ-011) se conserva como ruta literal y se compara **también
por texto normalizado** — un archivo que todavía no existe es exactamente donde dos comisiones
chocan». La comparación por texto sólo funciona **literal contra literal**: el otro REQ aporta su
**expansión**, nunca el texto de su patrón, así que el literal futuro nunca casa con el glob.

**Pasos de reproducción**

```bash
mk REQ-A 'hooks/post-bash.sh'   # REQ-011: el archivo aún no existe
mk REQ-B 'hooks/*.sh'
( cd "$P" && bash "$PAR" REQ-A REQ-B ); echo "rc=$?"
```

**Esperado:** `colisiona` — REQ-A va a crear `hooks/post-bash.sh` y el mapa de REQ-B lo cubre.
**Observado:** `REQ-A vs REQ-B  disjunto` · `Todos los pares son DISJUNTOS` · `rc=0`.

**Variante, mismo defecto, con directorio en vez de glob:**

```bash
mk REQ-A 'tools/nuevo.sh'; mk REQ-B 'tools/'
( cd "$P" && bash "$PAR" REQ-A REQ-B )   # -> disjunto, rc=0
```

Y el comentario de `expande()` (líneas 161-162) declara justo lo contrario para el caso simétrico:
«un DIRECTORIO arrastra todo lo que cuelga de él: declarar `tools/` y `tools/x.sh` por separado y
llamarlos disjuntos sería el falso negativo más fácil de producir». Lo es — cuando `tools/x.sh`
todavía no existe.

**Hueco del banco, señalado para el arreglo:** el caso 34 «un archivo que TODAVIA NO EXISTE se
compara como ruta literal» sólo prueba **literal contra literal** (REQ-712 y REQ-713 declaran los
dos `hooks/post-bash.sh`). No hay ni un caso literal-futuro contra glob, que es donde falla.

## QA-203 — un marcador de posición se acepta como ruta y responde `disjunto` con todo

**Clase:** `contrato` · **Severidad:** media-alta · **Criterio:** CA-04 de REQ-013.

CA-04: «un REQ **sin** línea `Archivos:`, **o con un valor que no se puede interpretar**, … se
declara `sin declarar`, colisiona con todos y sale ≠ 0». Un valor de una sola palabra sin barra es
indistinguible de una ruta futura para la herramienta, y gana la lectura optimista.

**Pasos de reproducción**

```bash
mk REQ-B 'hooks/lib.sh'
for v in TBD pendiente todo N/A - '?'; do mk REQ-A "$v"; ( cd "$P" && bash "$PAR" REQ-A REQ-B ); echo "rc=$?"; done
```

**Esperado:** `sin declarar`, `colisiona`, rc ≠ 0 en los seis.
**Observado:** `disjunto` y **rc=0** en los seis. (Sólo caen bien las formas con blanco —`por
definir`— o las que quedan vacías tras el paréntesis —`(pendiente)`—, y eso por accidente de otra
regla, no porque se juzgue el valor.)

Un REQ cuyo autor todavía no sabe qué va a tocar es el caso en que más importa **no** decir
«adelante», y es justo el que sale verde.

## QA-204 — `Archivos:` duplicado: gana el primero; el lector de las puertas resuelve con el último

**Clase:** `contrato` · **Severidad:** media · **Criterios:** CA-02, CA-03 de REQ-013.

`lee_campo_archivos()` (`tools/arnes-paralelo.sh:100-109`) hace `return 0` en la **primera**
aparición. `arnes_campos_req` de `hooks/lib.sh` —el lector que gobierna a las dos puertas— recorre
toda la cabecera **sin salir**, de modo que en `QA:`, `Seguridad:`, `Rigor:` y `Hallazgos abiertos:`
gana la **última** aparición. CA-03 exige «**exactamente** la misma normalización … la misma
función, reutilizada, no una copia»: la precedencia ante duplicados diverge, y diverge hacia el lado
que abre.

**Pasos de reproducción**

```bash
printf '# REQ-A\nEstado: en-revisión\nArchivos: (ninguno)\nArchivos: hooks/lib.sh\n\n## H\n' \
  > "$P/requirements/REQ-A.md"
mk REQ-B 'hooks/lib.sh'
( cd "$P" && bash "$PAR" REQ-A REQ-B ); echo "rc=$?"
```

**Esperado:** o bien el mismo criterio de precedencia que el lector de las puertas (gana
`hooks/lib.sh` → `colisiona`), o bien `sin declarar` por cabecera ambigua (fail-closed).
**Observado:** `REQ-A  en-revision  (ninguno)` · `REQ-A vs REQ-B  disjunto` · `rc=0`.

## QA-205 — `~`, enlaces simbólicos y mayúsculas: tres falsos `disjunto` que CA-11 deja fuera

**Clase:** `instrumento` · **Severidad:** baja-media · **Dueño:** `desarrollador` · **Criterio:** CA-11 de REQ-013.

Ninguno cambia hoy el veredicto de ningún REQ real del repositorio (no hay enlaces simbólicos ni
rutas con `~` declaradas, y el sistema de archivos de CI distingue mayúsculas), así que no bloquea.
Se registra como deuda porque los tres son la **misma causa**: CA-11 enumera cuatro formas concretas
en vez de enunciar la propiedad «toda ruta que no sea relativa a la raíz, o que pueda designar el
mismo archivo por otro nombre, se rechaza».

| Entrada | Esperado | Observado |
|---|---|---|
| `~/secretos.sh` vs `hooks/lib.sh` | rechazo con motivo (no es relativa a la raíz) | `disjunto`, rc 0 — se trata como un directorio literal llamado `~` |
| `hooks/lib.sh` vs `hooks/alias.sh` (enlace simbólico a `lib.sh`) | `colisiona` | `disjunto`, rc 0 |
| `Hooks/Lib.sh` vs `hooks/lib.sh` | correcto en Linux; falso en Windows/macOS | `disjunto`, rc 0 |

El tercero **sube a `contrato`** si se mide sobre un sistema de archivos que no distingue
mayúsculas: `AGENTS.md` §2 declara Windows/MSYS como plataforma del desarrollador y ahí dos REQ que
declaren `Hooks/Lib.sh` y `hooks/lib.sh` van al mismo archivo. **No lo he podido medir**: no dispongo
de esa plataforma.

## QA-208 — CA-21 de REQ-012 escribe un criterio de coste como igualdad (la forma que prohíbe)

**Clase:** `contrato` · **Forma:** `igualdad` · **Severidad:** media · **Criterios:** CA-04 contra CA-21 de REQ-012.

CA-04 prohíbe por nombre escribir un criterio de coste como igualdad. CA-21 lo hace:

> «Entonces el coste en comisiones **es 1 del analista** (redacción) más **1 del desarrollador**
> (espejo en plantillas y agentes) y **0 comisiones nuevas por REQ** en adelante»

Las comisiones son coste (el REQ las cuenta en horas y en el libro de comisiones de
`docs/qa/1.32.0.md`). Escrito como igualdad, **gastar menos incumple el criterio**, que es
literalmente el defecto que costó la vuelta entera del bucle en el ciclo 2 y que este REQ existe
para erradicar.

**Y ya está desmentido, sin necesidad de esperar al cierre.** La propia Trazabilidad de REQ-012
registra **dos** comisiones de `analista-requerimientos`:

```
Tocado por: analista-requerimientos / 2026-09-06 · analista-requerimientos (reordenación de
ventanas…) / 2026-09-06 · desarrollador (implementación…) / 2026-09-06
```

**Forma correcta (la escribe el analista, no el QA):** «**no más de** 1 comisión de analista y 1 de
desarrollador; **menos es conforme y no es hallazgo**», o el techo que el ciclo real justifique.
La tabla «Coste del propio cambio (REQ-012)» de `docs/qa/1.32.0.md` arrastra la misma redacción
(«Presupuestado 1 / 1») y necesita el mismo arreglo.

## QA-209 — CA-02 de REQ-012 delimita su alcance enumerando (la forma que prohíbe), y se hereda

**Clase:** `contrato` · **Forma:** `enumeración` · **Severidad:** media · **Criterio:** CA-02 de REQ-012.

CA-02 dice que un criterio que enumere **dos o más** elementos concretos sin (i) la marca
`no exhaustivo` **o** (ii) el puntero al sitio único está mal formado. Y a continuación delimita su
propio alcance así:

> «Dado un criterio que se refiere a un conjunto de cosas que el código reconoce **(envoltorios,
> prefijos, separadores, extensiones, estados)**…»

Cinco elementos concretos, sin marca `no exhaustivo` y sin puntero. Leída al pie de la letra —que es
como se leen los contratos en este arnés—, la regla **no alcanza** a un criterio que enumere roles,
banderas, tipos MIME, códigos de salida o clases de hallazgo: envejece hacia el lado que abre,
exactamente como la lista de envoltorios del caso medido.

**No es cosmético: se hereda.** El mismo paréntesis está en `requirements/README.md:«Regla»` de la
sección (a) y, por espejo (CA-07), en `templates/requirements-README.md.tpl`, que es lo que
`arnes-upgrade` lleva a todos los proyectos consumidores.

**Arreglo por propiedad, no añadiendo palabras a la lista** (la propia regla lo dice): «un conjunto
de cosas que el código reconoce — ejemplos **no exhaustivos**: envoltorios, prefijos, estados».

## QA-210 — CA-23 es falso sobre el árbol entregado, y CA-11 pasa hoy por un accidente de indexación

**Clase:** `contrato` · **Severidad:** media · **Criterios:** CA-11 y CA-23 de REQ-012.

Los dos criterios afirman una propiedad del **árbol completo** y se la atribuyen a **un** REQ, en una
ventana que REQ-012 comparte por decisión explícita con REQ-013 y REQ-014.

**CA-23 — falla ahora, medido.** «…y `CASOS_ESPERADOS` **no cambia**»:

```
$ git show v1.31.0:tests/escenarios/hooks/run.sh | grep '^CASOS_ESPERADOS='   -> 683
$ grep -n 'CASOS_ESPERADOS=' tests/escenarios/hooks/run.sh                     -> 716
```

**CA-11 — pasa hoy, y dejará de pasar en el commit siguiente.** Ahora mismo:

```
$ git diff v1.31.0 --stat -- hooks/ tools/      (vacío)
$ git status --porcelain -- hooks/ tools/
?? tools/arnes-paralelo.sh
```

El diff está vacío **sólo porque `tools/arnes-paralelo.sh` está sin comitear**. En cuanto se
indexe —que es condición de CA-30 de REQ-013, que exige verlo en modo `100755` en el índice del
PR—, `git diff v1.31.0 -- tools/` deja de estar vacío y CA-11 falla. Un control que se autodestruye
al hacer el commit no acredita nada.

**Lo que el criterio quiere decir es verificable, y lo he verificado:** REQ-012 **no** añade máquina.
`git diff v1.31.0 -- hooks/` está vacío, `hooks/hooks.json` y `hooks/campos-req.awk` están
intactos, y el único archivo nuevo bajo `tools/` es el de REQ-013. Lo que falla es la **redacción
del control**: debe acotarse a los cambios atribuidos a REQ-012 (que son `requirements/README.md`,
`templates/`, `agents/`, `skills/`, `AGENTS.md` §9 y `docs/qa/`), no al árbol entero de una ventana
compartida.

**Misma raíz que el CA-14 ya conocido** (que confirmo arriba y no reabro): un control escrito como
`git diff` sobre un árbol compartido, sin base declarada o sin alcance por REQ.

```bash
k="${d[a]}|${d[b]}"        # línea 377
```

Eso es cierto para las rutas que se expanden contra el árbol, porque los REQ se recorren de 0 a
N-1. Pero la pasada de los futuros **añade dueños fuera de orden**:

```bash
DUENOS[$r]="${DUENOS[$r]:-} $a "   # línea 358 — `a` puede ser MENOR que el dueño ya presente
```

positivo): `docs/nuevo.md` (futuro, ajeno) vs `hooks/*.sh` → `disjunto`, rc 0. ✔

### El aviso de SEC-020 — las dos mitades, verificadas

| Mitad del aviso | Entrada | Resultado medido |
|---|---|---|
| «el marcado **por elemento** no es fiable» | `` `hooks/lib.sh`, `tools/x.sh` `` | mapa **corrompido** (`hooks/lib.sh\``, `` `tools/x.sh ``) → **`disjunto` / rc 0** sobre rutas que no existen |
| idem, con el otro marcador del ejemplo | `_hooks/lib.sh_, _tools/x.sh_` | mapa `hooks/lib.sh_`, `_tools/x.sh` → **`disjunto` / rc 0** |
| «envolver la **línea entera** sí se lee bien» | `` `hooks/lib.sh, tools/x.sh` `` | mapa correcto → `colisiona tools/x.sh` / rc 1 |
| idem, subrayado | `_hooks/lib.sh, tools/x.sh_` | mapa correcto → `colisiona` / rc 1 |
| idem, negrita y cursiva | `**a, b**` · `*a, b*` | mapa correcto → `colisiona` / rc 1 |

**Las dos mitades son ciertas.** El mecanismo queda medido: el desenvoltorio se aplica al **valor
entero** antes de separar la lista, así que cuando el **primero y el último** elemento llevan el
mismo marcador el par exterior se arranca de dos elementos distintos y los dos quedan impares.
Decorar **un solo** elemento (`a/uno.sh, **b/cuatro.sh**`) sí se lee bien — el aviso dice menos que
la máquina, que es la dirección segura, y por eso no es hallazgo.

## Hallazgos de este pase

**Nada de clase `usuario/dinero` ni `contrato` es nuevo en el delta.** Lo que se abre es deuda
`instrumento` con dueño y ventana; **no bloquea el cierre de nada**.

### QA-214 (`instrumento`) — el inventario base no es un artefacto, y por eso este pase costó una reconstrucción

- **Reproducción:** intentar verificar «ningún caso anterior cambió de veredicto» sobre el árbol de
  735 casos. `git` no tiene esa base: toda la ventana está sin comitear.
- **Esperado:** un inventario fechado de la corrida que la firma acreditó, en disco.
- **Observado:** no existe. La base hubo que **reconstruirla** por mutación del código de producción
  y acotación por `mtime`. Funciona —y este pase lo demuestra—, pero depende de que nadie haya
  tocado el reloj ni un archivo sin cambiarlo de contenido.
- **Severidad:** media (de método). **Dueño:** `desarrollador`. **Ventana:** 1.33.0.
- **Arreglo propuesto:** que la corrida que sostiene un veredicto deje
  `tests/escenarios/hooks/inventario.sh` volcado en `docs/qa/inventario-<versión>.txt`, comiteado.
  Un `diff` contra un archivo es evidencia; una reconstrucción es un argumento.

### QA-215 (`instrumento`) — el elemento vacío entre separadores se descarta sin decirlo

- **Reproducción:** `Archivos: a/uno.sh,, b/cuatro.sh` y `Archivos: a/uno.sh, b/cuatro.sh,`.
- **Esperado (lectura literal de CA-03):** «el número de elementos que la herramienta **evalúa** es
  igual al número de elementos separados por comas del valor declarado» → 3.
- **Observado:** evalúa **2**; el elemento en blanco se salta en silencio (`[ -z "${buf//[[:blank:]]/}" ]`).
- **Por qué es `instrumento` y no `contrato`:** la **propiedad** que manda —«ningún elemento
  **declarado** desaparece en silencio»— se cumple: un elemento vacío no declara nada, las dos rutas
  llegan íntegras al mapa y el veredicto es el correcto (`colisiona`). La discrepancia es con el
  **método de verificación por conteo**, no con el comportamiento, y la dirección es la segura.
- **Severidad:** baja. **Dueño:** `desarrollador`. **Ventana:** 1.33.0, junto con SEC-020 — si se
  restringe la gramática del campo, la coma doble pasa a ser un error nombrado y esto se cierra solo.

### QA-216 (`instrumento`) — amplía SEC-020, no lo duplica: la corrupción también ocurre con `**`

- **Reproducción:** `Archivos: **a/uno.sh**, **b/cuatro.sh**` frente a un REQ que declara
  `b/cuatro.sh`.
- **Observado:** el mapa sale corrompido igual (`a/uno.sh**`, `**b/cuatro.sh`), y el veredicto
  **`colisiona`** salió **por accidente**: `**b/cuatro.sh` casó como glob contra el árbol. Con otro
  nombre de directorio, la misma corrupción daría `disjunto`.
- **Clase y destino:** es la **misma clase** que **SEC-020** (`contrato`, **abierto**, dueño
  `desarrollador`, ventana 1.33.0), que ya está declarado y cuya respuesta de fondo —restringir la
  gramática— es un cambio de contrato. **No abro hallazgo nuevo**: se anota como evidencia adicional
  del alcance de SEC-020, para que el arreglo de 1.33.0 no se limite a los acentos graves y el
  subrayado que hoy nombra el aviso.
- **Nota:** el documento que gobierna cómo se escribe el campo **ya cubre** este caso, porque manda
  la ruta **desnuda** («la única forma medida como segura»). No hay overclaim.
